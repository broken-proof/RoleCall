# RoleCall

RoleCall lets DECA chapters run roleplay practice remotely. Students (trainees) record and upload roleplay videos, trainers are assigned to mark them, and each mark produces a score and written feedback, so nobody has to meet in person.

- `backend/`: Spring Boot (Java, Maven), Spring Data JPA, PostgreSQL on AWS RDS, AWS S3 for video files, JWT auth, Gmail SMTP for verification and reset emails.
- `frontend/`: React + TypeScript + Vite.

Backend package root: `backend/src/main/java/com/newbyproof/rolecall/`

## Database

- PostgreSQL. Connection settings come from env vars or `backend/.env` (see `application.properties`).
- The schema is generated by Hibernate (`spring.jpa.hibernate.ddl-auto=update`). There are no migration files (Flyway/Liquibase), so the entity classes are the schema. Renaming or removing a field does **not** drop the old column.
- Entities and enums live in `entity/`. Repositories live in `repository/`.
- ID types are mixed: `User` uses an auto-generated `Integer`, and every other entity uses a `UUID`.

### Entity relationship overview

```
School 1 ──< User >── 1 Cluster          School.admin ── 1 User (school admin)
                │
                │ trainee
                ▼
  Roleplay 1 ──< Video 1 ──< VideoTrainer >── 1 User (trainer)     (marking assignment)
     │            │
     │            └──< Evaluation >── User (trainer), User (trainee)   (score + feedback)
     ▼
  Cluster
```

A `Video` **is** a submission: one row per attempt, each with its own unique S3 file. A student can perform the same `Roleplay` many times, and each attempt is a separate `Video`.

### Lombok conventions for entities

- Entities use `@Data`, `@NoArgsConstructor` and `@AllArgsConstructor`.
- Any back-reference that would recurse must be marked `@ToString.Exclude` and `@EqualsAndHashCode.Exclude`. That covers `@OneToMany` collections and `School.admin`. Without the exclusions, `toString`/`hashCode` loop forever between the two entities.
- Don't cascade from a parent onto `User`. Deleting a `School` or `Cluster` must never delete users.

### Entities

#### `User` (table `users`), the [User.java](backend/src/main/java/com/newbyproof/rolecall/entity/User.java) file
One account for every person in the system. Implements Spring Security `UserDetails`.

| Field | Type | Notes |
|---|---|---|
| `id` | `Integer` | PK, `GenerationType.AUTO` |
| `username` | `String` | unique, not null |
| `email` | `String` | unique, not null |
| `password` | `String` | not null (hashed) |
| `enabled`, `accountNonExpired`, `accountNonLocked`, `credentialsNonExpired` | `boolean` | default `true` |
| `verificationCode` | `String` | column `verification_code`, used for email verification |
| `verificationExpiration` | `LocalDateTime` | column `verification_expiration` |
| `school` | `School` | `@ManyToOne` LAZY, FK `school_id` |
| `cluster` | `Cluster` | `@ManyToOne` LAZY, FK `cluster_id`, the user's DECA career cluster |
| `role` | `Role` enum | stored as a string: `TRAINER`, `TRAINEE`, `ADMIN`. Defaults to `TRAINEE` |

`getAuthorities()` returns `ROLE_<role>` (e.g. `ROLE_TRAINER`), so Spring Security `hasRole("TRAINER")` checks work. A user with a `null` role gets no authorities. A student belongs to exactly one cluster.

#### `Video` (table `video`), the [Video.java](backend/src/main/java/com/newbyproof/rolecall/entity/Video.java) file
A student's roleplay submission, one row per attempt. The file itself lives in S3, and this row holds its metadata.

| Field | Type | Notes |
|---|---|---|
| `id` | `UUID` | PK |
| `trainee` | `User` | `@ManyToOne` (EAGER by default), FK `trainee_id`, the student who submitted it |
| `roleplay` | `Roleplay` | `@ManyToOne` (EAGER), FK `roleplay_id`, the scenario performed. Nullable for now (see gaps) |
| `title` | `String` | |
| `storageKey` | `String` | **unique**. S3 key in the format `videos/{traineeId}/{uuid}_{filename}`, so every submission has its own file |
| `contentType` | `String` | MIME type |
| `status` | `VideoStatus` enum | `PENDING` → `UPLOADED` → `REVIEWED` |
| `createdAt` | `Instant` | set when the upload completes, not when the row is created |

Upload flow (`VideoService`): `POST /api/video/upload-url` takes an optional `roleplayId`. `createUploadRequest` then saves a `PENDING` row linked to that roleplay and returns a presigned S3 PUT URL. The client uploads directly to S3. `completeUpload` then sets the row to `UPLOADED` and stamps `createdAt`.

### Repositories

All repositories extend `JpaRepository`, which provides `save`, `findById`, `findAll`, `delete` and the other standard CRUD methods. The table below lists only the custom finders each one adds.

| Repository | Key type | Custom queries |
|---|---|---|
| `UserRepository` | `Integer` | `findByUsername`, `findByEmail`, `findByUsernameOrEmail`, `findByVerificationCode` (all `Optional<User>`) |
| `SchoolRepository` | `UUID` | `findByName`, `findByNameIgnoreCase` (`Optional<School>`) |
| `ClusterRepository` | `UUID` | none |
| `RoleplayRepository` | `UUID` | none |
| `VideoRepository` | `UUID` | `findAllByTraineeId(Integer)`, `findAllByRoleplayId(UUID)` |
| `VideoTrainerRepository` | `UUID` | `findByVideoId`, `findByTrainerId`, `findByVideoIdAndTrainerId` (`Optional`), `findByStatus(MarkingStatus)`, `findByTrainerIdAndStatus` |
| `EvaluationRepository` | `UUID` | `findByVideoId`, `findByTrainerId`, `findByVideoIdAndTrainerId` (`Optional`), `findByVideoIdOrderByGradedAtDesc` |

### Known gaps and pitfalls in the current model

Keep these in mind when changing entities or writing services:

- **`Video.roleplay` is nullable.** Existing rows have no roleplay, and the frontend doesn't send `roleplayId` yet. Make it `nullable = false` once the frontend sends it and old rows are backfilled.
- **Entities are serialized directly to JSON.** `VideoController` returns `Video` entities, so the trainee's `User` is included, password hash and all. Lazy relations such as `User.school` can also fail to serialize. Return DTOs instead.
- **No uniqueness on (video, trainer)** in `VideoTrainer` or `Evaluation`. If duplicates exist, `findByVideoIdAndTrainerId` (which returns an `Optional`) throws `IncorrectResultSizeDataAccessException`. Consider `@Table(uniqueConstraints = ...)`.
- **`Evaluation.trainee` duplicates `Video.trainee`**, so the two can drift apart. Set it from the video, or derive it from the video instead of storing it.
- **Existing users with a `null` role get no authorities.** Backfill them, e.g. `UPDATE users SET role = 'TRAINEE' WHERE role IS NULL`.
- **`VideoStatus.REVIEWED` and `MarkingStatus.MARKED` overlap.** Nothing currently moves a video to `REVIEWED` when its assignments or evaluations finish.
- `Video.createdAt` is `null` while the video is `PENDING`.
- `Video.trainee`, `Video.roleplay` and `Roleplay.cluster` use EAGER fetch, unlike the LAZY fetches everywhere else. `Video.roleplay` is deliberately EAGER: `Video` is returned as JSON, and a lazy Hibernate proxy would fail to serialize.
- Changing a cascade or constraint in the entities doesn't change existing database constraints under `ddl-auto=update`. The new unique constraint on `video.storage_key` is only added if no duplicate keys already exist.
